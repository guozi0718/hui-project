### 联系客服功能产品需求文档｜智小徽小程序（教师端＋家长端）

产品版本：v1.23（第一期 · 优化展示）  
文档编号：PRD-MP-CS-20261125  
文档版本：V2.11  
适用端：智小徽小程序（内置可切换教师端、家长端双身份）

---

#### 1. 需求背景与业务目标

智小徽小程序内置可切换的“教师”与“家长”两种使用身份。老师与家长在日常使用智能校徽、校园考勤、请假及消息提醒过程中遇到疑问时，需要从小程序“我的”页快速查看常见问题解答，并联系当前学校对应的专属客服或负责机构默认客服进行电话咨询。本期针对小程序联系客服模块重点进行**展示与交互体验优化**，承接运营后台与代理商端维护的客服配置数据，确保不同负责机构学校下的客服电话准确展示、排版紧凑清晰、无越权兜底与误拨风险。

本期核心目标：

1. **双身份学校上下文精准隔离**：家长端严格按当前选中孩子的有效就读学校获取客服名单，教师端严格按当前任职学校获取客服名单；切换身份、切换孩子或切换学校后立即重新解析对应客服，绝不串用其他学校或另一身份的客服缓存。
2. **代理商零客服不兜底硬规则落地**：当学校由代理商负责且该代理商尚未创建任何自有客服（自建客服数量为 0）时，小程序直接按“无客服”展示，绝不使用运营后台的平台默认客服兜底，避免平台客服误接未建客服代理商学校的咨询电话。
3. **专属优先与机构默认分层解析**：对于已配置客服的代理商学校及平台直营学校，严格执行“学校专属客服优先、机构唯一默认客服兜底”规则；1 所学校绑定多名专属客服时完整展示全部有效人员。
4. **联系客服弹窗紧凑排版与视觉统一**：统一单人与多人客服的底部弹窗体验（不点击入口直接拨号）；不展示后台内部客服类别标题；将“客服姓名＋联系电话”紧凑同行左对齐并匹配右侧同行拨打按钮，“工作时间”独占次行完整换行展示；电话号码统一采用与页面正文一致的字体颜色，不使用绿色高亮；“帮助与反馈”页联系入口留白紧凑清晰。
5. **异常状态与动态变更安全闭环**：区分“代理商未创建客服”“未设置默认客服”“数据读取失败”“身份/绑定失效”等不同场景，确保非工作时间不拦截紧急拨号、系统拨号取消或失败不自动改拨他人。

| 电话拨打与返回保持 | 点击指定客服右侧“拨打”按钮唤起手机系统拨号界面并填入该客服对应号码；工作时间外不拦截拨打；取消拨号或关闭弹窗后完整保留当前《帮助与反馈》或《办理详情》页面状态与当前学校上下文。 |

##### 2.2 本期不包含范围

本期不在小程序内提供：客服人员新增/编辑/删除管理功能、客服关联学校或切换默认客服的配置入口、小程序内实时文字/语音在线聊天客服窗口、常见问题词条的小程序端编辑功能、拨号通话录音或通话时长统计。

#### 3. 核心业务概念、权限矩阵与全局一致性规则

##### 3.1 核心业务对象与基础规则

| 业务概念 | 业务定义与数据来源 | 核心业务规则 |
| --- | --- | --- |
| 当前学校上下文 | 决定展示哪组客服的唯一学校依据 | **家长身份**取当前选中且绑定有效孩子的所属学校；**教师身份**取当前登录教师有效任职学校。同一账号切换家长/教师身份、或家长切换名下不同孩子时，立即按新学校重新获取客服数据，绝不沿用上一上下文缓存。 |
| 学校负责机构类型 | 学校在后台归属的服务主体类型 | 分为**“代理商负责”**与**“运营平台直营”**两类。学校负责机构类型直接决定客服解析分支及默认兜底来源，两套兜底体系严格隔离、互不穿透。 |
| 代理商自建客服数 | 当前负责代理商名下未删除的自有客服总数 | 由运营后台或代理商端创建的归属该代理商的客服计入此数量（运营关联给该代理商的平台临时客服仍归属平台，不计入代理商自建客服数）。**当代理商自建客服数量为 0 时，直接触发“无客服不兜底”最高优先级规则。** |
| 学校专属客服 | 后台明确与当前学校建立有效绑定关系的客服 | 1 所学校可同时绑定 1 名或多名专属客服（可同时包含代理商客服与已关联该代理商的平台客服）。注意：**仅将平台客服关联到某代理商、但未勾选绑定具体学校时，该平台客服不属于该校专属客服。** |
| 机构默认客服 | 运营平台或单家代理商设置的唯一兜底客服 | 仅当当前学校未绑定任何有效专属客服时启用：平台直营学校读取运营平台默认客服；已建有自有客服的代理商学校读取该代理商设置的默认客服（若该代理商尚未设置有效默认客服，则按无客服处理，绝不跨级拿运营平台默认客服顶替）。 |
| 工作时间展示格式 | 后台配置的每周工作星期与单组起止时段 | 每周工作日期按周一至周日自然顺序**逐日顿号罗列，不缩写合并连续星期**（例如展示为`每周一、周二、周三、周四、周五 09:00-18:00`或`每周一、周三、周四、周五、周六、周日 8:30-17:30`）；仅作服务时段告知，不限制非工作时段拨号。 |
| 客服排序优先级 | 多名专属客服并存时的列表展示次序 | 弹窗内不显示客服类型标题，但内部固定按：**1. 代理商客服排在平台客服之前** → **2. 同类型按客服姓名中文拼音升序** → **3. 同名按纯数字电话号码升序** → **4. 仍相同按工作时间文本与系统记录先后稳定排列**。 |

##### 3.2 双身份角色权限与客服解析矩阵

| 身份 / 学校与后台配置状态 | 「客服电话」入口表现 | 点击「客服电话」响应结果 | 权限校验时机与边界要求 |
| --- | --- | --- | --- |
| 家长（有效绑定孩子）或教师（有效任职），且学校为**代理商负责、代理商自建客服数 = 0** | 图标＋“客服电话”＋右侧灰字**“暂无客服信息”** | **不打开弹窗**，轻提示**“暂无客服信息”** | 进入《帮助与反馈》页、切换孩子/身份、点击“客服电话”时均校验；最高优先级拦截，严禁展示运营平台默认客服或其他学校号码。 |
| 学校为**代理商负责、自建客服数 > 0**，且当前学校**存在有效专属客服** | 图标＋“客服电话”（不附带人名或号码） | 打开《联系客服》弹窗，展示该校**全部有效专属客服**（单人/多人同弹窗） | 打开弹窗与点击“拨打”时复核关系有效性；已删除客服或已解绑客服立即剔除。 |
| 学校为**代理商负责、自建客服数 > 0**，且当前学校**无专属客服** | 图标＋“客服电话” | 有代理商默认客服时打开弹窗展示该唯一默认客服；代理商未设有效默认客服时**不打开弹窗**，轻提示**“暂无客服信息”** | 严禁因代理商默认客服未设置而私自回退展示运营平台默认客服。 |
| 学校为**运营平台直营**，且当前学校**存在有效专属客服** | 图标＋“客服电话” | 打开《联系客服》弹窗，展示该校**全部有效专属客服** | 多名平台专属客服按姓名拼音与号码稳定排序展示。 |
| 学校为**运营平台直营**，且当前学校**无专属客服** | 图标＋“客服电话” | 平台已设默认客服时打开弹窗展示该默认客服；平台默认缺失时**不打开弹窗**，轻提示**“暂无客服信息”** | 平台默认客服缺失时严禁编造虚拟电话号码。 |
| 账号无有效学校上下文（如未绑定学生 / 无有效任职） | 图标＋“客服电话” | 不沿用任何历史学校缓存；按无学校规则处理或提示先完成身份/学生核验 | 切换身份、孩子解绑或教师离职后立即清除原学校客服缓存。 |
| 登录失效或无访问资格 | 无法停留在业务内页 | 拦截并引导重新登录或完成身份认证 | 登录过期时立即关闭已打开的客服弹窗，不继续暴露学校客服名单。 |

##### 3.3 全局数据一致性、并发变更与动态权限变化总则

1. **后台配置变更即时同步原则**：当运营后台或代理商端新增了首名客服（使代理商自建客服数从 0 变为大于 0）、修改了客服姓名/电话/工时、调整了学校专属绑定、切换了默认客服，或学校负责机构发生了转移（原专属客服自动解绑）时，小程序重新进入《帮助与反馈》或重新点击“客服电话”时均按最新生效结果展示，不固守过期的“暂无客服信息”或已失效的旧电话缓存。
2. **“读取失败”与“真实无客服”严格区分原则**：当因网络异常或服务繁忙未能获取到当前学校的负责机构类型或客服配置时，点击“客服电话”明确提示读取异常并支持重试，**严禁把网络失败误判为“代理商自建客服数为 0”，也严禁在读取失败时悄悄拿上一所学校的缓存号码或运营默认号码顶替展示**。
3. **弹窗浏览期间数据或权限动态变化保护**：
   - **孩子切换 / 身份切换**：从「我的」或首页切换孩子、切换家长/教师身份后再次进入本页，自动关闭此前残留的弹窗并按新身份、新学校重新读取；
   - **绑定解绑 / 任职失效 / 登录过期**：停留期间若家长与当前孩子的绑定被解除、教师任职权限被收回或登录态失效，再次点击入口或操作时立即清空原学校客服名单并按最新身份状态提示，绝不允许继续使用失效前的旧名单跨校拨号。
4. **单次点击精准拨号与防误触原则**：只有用户明确点击弹窗内某一位客服右侧的“拨打”按钮时，才触发该位客服号码的系统拨号动作；进入页面、展开常见问题、点击“客服电话”打开弹窗、上下滑动客服列表、点击右上角`×`或点击遮罩关闭弹窗，**任何情况下均绝不自动拨号**。

#### 5. 页面与功能详细说明

---

##### 5.1 「我的」页入口与《帮助与反馈》主页（CS-MP-01 / CS-MP-02）

###### 5.1.1 页面入口、导航与整体布局

1. **入口路径与标题对应关系**：用户在教师端或家长端底部导航切换至**「我的」**，点击功能区的**“帮助与客服”**按钮，进入二级页面，页面顶部导航栏居中标题固定显示**“帮助与反馈”**，左侧提供返回箭头 `‹`，右侧保留小程序标准胶囊区。
2. **稳定返回规则**：点击《帮助与反馈》左上角返回箭头 `‹`，直接返回当前身份的「我的」页，不跳回首页，也不误切换到另一身份页面；在本页内展开/收起常见问题、打开/关闭《联系客服》弹窗，均属于同页内交互，不额外叠加页面返回层级。
3. **页面主体两段式卡片结构**：自上而下固定由**“常见问题”卡片**与**“联系我们”卡片**两部分组成，背景与卡片圆角、字号严格沿用小程序统一视觉规范。

###### 5.1.2 页面区域与元素定义

| 所属区域 | 元素名称 | 默认状态与展示内容 | 交互与视觉要求 |
| --- | --- | --- | --- |
| 顶部标题栏 | 返回箭头 `‹` ＋ 页面标题 | 标题固定“帮助与反馈”（16 字号加粗） | 点击左侧 `‹` 关闭未收起浮层并返回「我的」页 |
| 常见问题卡片 | 卡片标题 | 固定显示“常见问题” | 左对齐常规卡片分组标题 |
| 常见问题卡片 | 问题折叠行列表 | 按配置顺序展示全部常见问题标题，右侧带 `+` 展开图标；**首次进入页面默认全部收起** | 点击任一问题行展开下方解答正文，右侧图标变为 `−`；再次点击该行收起解答并恢复 `+`；长问题与长答案均自动完整换行，不省略截断 |
| 联系我们卡片 | 卡片标题 | 固定显示“联系我们” | 位于常见问题卡片下方 |
| 联系我们卡片 | 「客服电话」入口按钮 | 左侧电话图标 ＋ 主文案“客服电话”；**当且仅当当前学校为代理商负责且代理商自建客服数为 0 时，下方/右侧附带灰字提示“暂无客服信息”** | **严禁在入口按钮上直接拼接展示某位客服的姓名、电话号码或工作时间**；点击后按 3.2 解析规则决定弹出《联系客服》弹窗或轻提示“暂无客服信息” |
| 联系我们卡片 | 「反馈建议」入口按钮 | 左侧反馈图标 ＋ 主文案“反馈建议” | 只保留图标与“反馈建议”主文案，不显示副文案，按钮内部上下留白紧凑，与左侧“客服电话”高度协调一致；点击进入《我的反馈》列表页 |

**交互、逻辑校验与异常场景**

1. **单名客服同样先开弹窗（不直接拨号）**：即使当前学校解析后只有 1 名可展示客服（如仅 1 名平台默认客服“李强”或 1 名代理商客服），点击“客服电话”也必须先打开《联系客服》弹窗让用户核对姓名、号码与工作时间，**绝不允许跳过弹窗直接调起手机拨号**。
2. **无客服场景点击反馈**：
   - 场景 A（代理商负责且代理商自建客服数 = 0）：入口内可见“暂无客服信息”，点击按钮不打开弹窗，屏幕弹出轻提示**“暂无客服信息”**（约 2.4 秒自动消失）；
   - 场景 B（代理商已建客服但当前既无学校专属客服也无有效代理商默认客服，或平台直营学校既无专属也无平台默认客服）：点击“客服电话”同样**不打开空弹窗**，轻提示**“暂无客服信息”**。
3. **常见问题空数据或加载异常保护**：若后台暂未配置常见问题或常见问题读取异常，“联系我们”卡片依然正常渲染可用，不能因常见问题异常导致用户无法点击“客服电话”或“反馈建议”。
4. **连续快速点击保护**：快速连续点击“客服电话”时只打开一层《联系客服》弹窗，不叠加多层遮罩或重复闪烁提示。

##### 5.2 《联系客服》底部半屏弹窗与拨号交互（CS-MP-03 / CS-MP-04）

当当前学校存在至少 1 名有效客服时，点击“客服电话”从屏幕底部滑出半屏弹窗，背景覆盖半透明暗色遮罩。

###### 5.2.1 弹窗字段与排版结构（本期核心展示优化）

| 弹窗位置 / 元素 | 展示内容与数据来源 | 排版对齐与字号颜色规范 |
| --- | --- | --- |
| 弹窗头部栏 | 左侧标题“联系客服”；右侧关闭图标 `×` | 头部固定不随列表滚动；标题 16 字号；点击 `×`、点击暗色遮罩空白处或按手机系统返回键均仅关闭弹窗 |
| 客服名单容器 | 单人或多人共用同一纵向列表区域；**不显示“代理商客服”“平台客服”等任何分组标题或身份标签** | 人员较多超出半屏最大高度时，仅名单容器内部纵向滚动，头部栏保持固定可见；各客服条目上下内边距收紧为紧凑间距（10 间距），避免松散大留白 |
| 第 1 行左侧：客服姓名 ＋ 联系电话 | 同行左对齐依次展示`客服姓名`与`联系电话`；10 位 `400` 服务号按 `400-XXX-XXXX` 分段展示，11 位手机号及带区号座机（保留前导 0）完整原样展示 | **姓名与电话处在同一水平行，两者横向间距紧凑固定（12 间距）**；正文 13 字号；**联系电话统一继承页面常规正文深灰蓝色，严禁使用绿色或刺眼高亮色**；号码与姓名一一严格绑定，长号码不截断 |
| 第 1 行右侧：「拨打」按钮 | 固定文案“拨打”（14 字号） | 每位有效客服各自拥有独立的“拨打”按钮；**按钮垂直方向仅与第 1 行（姓名＋电话行）居中对齐，绝不跨第 1 行与第 2 行工时总高度居中**，防止多行工时把按钮往下拉偏 |
| 第 2 行：工作时间 | 展示该客服完整的每周工作星期组合与起止时间（12 字号辅助说明色） | **独占姓名与电话的下一行左对齐展示**，支持多行自然完整换行，**严禁单行省略号截断**；工作日按周一至周日逐项完整列出（如：`每周一、周三、周四、周五、周六、周日 8:30-17:30`），不将连续日期缩写挤压 |

###### 5.2.2 排序、拨号逻辑校验与异常场景

1. **多客服混合展示与稳定排序校验**：
   - 当某代理商学校同时绑定了代理商自有客服（如“陈思远”“林晓雨”）和已关联该代理商的平台客服（如“李强”）作为学校专属客服时，弹窗将 3 人平铺在同一列表中：**代理商客服排在前面，平台客服排在后面**，中间不插入任何分组标题；
   - 同属代理商客服或同属平台客服的多人，按姓名中文拼音升序排列（如“陈思远”排在“林晓雨”前）；同名客服按纯数字号码升序区分；号码与工时仍相同时保持系统记录原始顺序，用户多次开关弹窗或滑动列表，人员顺序与“拨打”按钮指向始终固定不变，绝不错位拨给相邻人员。
2. **工作时间外不拦截拨打**：工作时间仅用于提示家长或老师该客服的常规当班时段；**无论当前手机时间是否在客服工作时段内（包括清晨、夜间、周末或法定节假日），“拨打”按钮始终保持正常可点击状态**，点击后直接唤起系统拨号，不弹出“当前非工作时间无法拨打”等阻断提示。
3. **精准拨号与号码有效性保护**：
   - 点击第 N 位客服右侧的“拨打”按钮，系统提取该名客服原始纯数字电话号码（展示用的 `400` 连字符不影响实际拨号数字，座机保留首位区号 `0`）交由手机系统拨号盘处理；
   - 若某条客服记录因历史脏数据导致电话号码为空或无有效数字，不得为该行生成错误拨号或拿默认客服号码冒充，点击时提示号码暂不可用；
   - 用户在手机系统拨号确认框点击“取消”、对方占线未接通或通话挂断返回小程序后，页面保持在当前《帮助与反馈》及已打开的《联系客服》弹窗状态，当前选中的孩子或教师学校上下文不变，**绝不自动重拨，也绝不自动跳拨列表中的下一位客服**。
4. **极端长文本排版保护**：当客服姓名较长（最多 50 字）且工作时间包含全周 7 天（`每周一、周二、周三、周四、周五、周六、周日 08:30-17:30`）时，左侧姓名区域自适应换行而不把右侧“拨打”按钮挤出屏幕边界，下方工作时间完整折行显示，不遮挡下一位客服条目。

#### 6. 跨端协同与界面交互通用规范

##### 6.1 与运营后台、代理商端的数据协同规则

| 协同场景 | 跨端联动与小程序表现规则 |
| --- | --- |
| 代理商从 0 创建第 1 名客服 | 代理商端或运营后台为该代理商创建首名自有客服并设为默认客服（或绑定学校专属客服）后，小程序该代理商负责学校脱离“自建客服数为 0”状态，重新进入页面即可正常打开弹窗查看并拨打该客服电话。 |
| 后台切换默认客服或修改资料 | 运营后台或代理商端修改了客服姓名、电话、工作时间或切换了机构默认客服后，小程序再次打开《联系客服》弹窗实时展示最新姓名、号码与逐日工时。 |
| 运营解除平台客服与代理商关联 | 解除关联会同步清理该平台客服在该代理商名下绑定的学校专属关系，小程序对应学校的客服弹窗立即移除该名平台客服。 |
| 学校负责机构发生变更 | 学校从 A 代理商转归 B 代理商或转平台直营时，后台自动解除该校全部原专属客服关系；小程序立即按新负责机构的自建客服数及默认客服规则展示（若新代理商自建客服数为 0，立即变为“暂无客服信息”，绝不残留旧机构客服或误回退平台默认客服）。 |

##### 6.2 统一版式与交互体验规范

1. **字号层级统一**：参照小程序内页标准层级——页面顶部导航标题与底部弹窗主标题统一 16 字号，卡片分栏标题 14.5 字号，客服姓名、电话与问题正文 13 字号，工作时间等辅助说明文字 12 字号，“拨打”等操作按钮 14 字号。
2. **颜色克制统一**：客服电话号码统一使用与客服姓名同色系的常规正文色，不使用绿色高亮字，仅右侧“拨打”按钮采用主题强调样式，保证视觉干净耐看。
3. **弹层关闭优先级**：当《联系客服》半屏弹窗与演示说明面板同时涉及返回关闭时，优先逐层关闭最上层浮层，回到《帮助与反馈》本页，绝不因一次点击关闭连带退回「我的」页或首页。
