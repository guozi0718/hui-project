# 智小徽小程序联系客服功能产品需求文档

文档版本：v1.0  
定版日期：2026-11-25  
适用产品：内置家长、教师两种可切换身份的智小徽小程序  
功能版本：家长端 v0.33、教师端 v0.34，并纳入代理商未创建客服时不兜底的规则；完整小程序定版版本为双端 v1.0。

## 1. 范围与入口

本功能为“我的 → 帮助与反馈 → 客服电话”及点击后出现的“联系客服”弹窗。它不是客服人员管理后台，不在小程序新增客服管理菜单、二级菜单、人员新增或学校分配页面。

帮助与反馈保留“常见问题”和“联系我们”区域；联系我们包含“客服电话”和“反馈建议”两个入口。反馈建议只保留主标签及图标，不显示副文案“问题与建议”。常见问题默认全部收起，点击可展开和再次收起。本功能不修改问题、答案及其他业务内容。

## 2. 当前角色和学校上下文

| 使用身份 | 当前学校的取得方式 | 切换要求 |
|---|---|---|
| 家长 | 当前所选学生的有效学校关系 | 切换孩子或学校后重新取得对应客服电话，不能沿用另一孩子学校的号码 |
| 教师 | 当前教师身份的有效任职学校 | 切换任职学校或角色后重新取得，不串用家长角色的学校资料 |

同账号双身份共享框架，不共享错误的学校上下文。客服电话配置可由代理商或运营方维护，页面展示必须根据当前学校的负责类型及有效客服关系决定。

## 3. 客服解析规则

### 3.1 优先判定：代理商未创建客服

**当学校由代理商负责，且该代理商尚未创建客服，即代理商创建客服数量为0时，当前学校直接按无客服展示。不得采用运营后台默认客服兜底。**

该条件必须先于现成默认号码、演示单客服数据或缓存名单判定。不能因为存在运营默认客服就显示该号码，也不能沿用另一学校或另一身份的联系人。此场景不生成虚拟客服，不自动拨号，不显示任何兜底电话号码。

创建数量未知、接口读取失败与已核验为0不是同一情况。正式服务应返回可信的学校负责类型和客服创建事实，客户端不能把失败随意解释成“已无客服”或“可以兜底”。

### 3.2 其他有客服场景

| 场景 | 本端采用方式 |
|---|---|
| 代理商负责，创建客服数为0 | 直接无客服；不使用运营默认客服或缓存号码 |
| 代理商负责，已创建客服，学校存在有效专属客服 | 展示当前学校的全部有效专属客服 |
| 代理商负责，已创建客服，学校没有专属客服 | 根据该代理商已确认配置读取其唯一默认客服；默认不存在时按其有效联系人配置处理，不因缺省就自行改用运营默认客服 |
| 平台直营，学校存在专属客服 | 展示该学校有效专属客服 |
| 平台直营，无学校专属客服 | 采用平台已配置的默认客服；默认缺失时无号码，不虚构 |
| 无有效学校上下文 | 不采用其他学校缓存；按产品现有平台默认配置处理，身份或学校读取失败另行提示 |

学校专属关系须已经有效保存；仅把平台客服关联到某代理商，不等于已成为该学校的专属客服。学校负责机构变更后，不能继续展示已经失效的专属关系。

## 4. 帮助与反馈页面中的入口

客服电话入口固定显示本功能图标及“客服电话”，不在入口上混入某位客服的姓名、号码或工作时间。

只要存在可展示的客服，点击入口即打开“联系客服”弹窗。单人和多人使用同一套弹窗，不因只有一人就自动拨号。

在代理商未创建客服场景，入口旁显示“暂无客服信息”；点击后提示“暂无客服信息”，不打开带平台默认号码的名单。其他无客服配置同样不得生成号码或错误拨打动作。

该入口不包含客服配置或用户资料查询。点击、关闭及切换客服场景均不创建新的业务页面。

## 5. 联系客服弹窗

### 5.1 字段与排版

| 项目 | 当前显示要求 |
|---|---|
| 标题 | “联系客服”，使用同端现有标题样式 |
| 名单 | 单人和多人均在同一名单区域展示 |
| 分组标题 | 不显示“代理商客服”“平台客服”等类别标题 |
| 姓名和号码 | 同一行、左对齐；间距紧凑，号码必须对应当前姓名 |
| 工作时间 | 独占姓名和号码的下一行，显示该人员完整工作日及时间范围 |
| 拨打 | 每位有效联系人独立按钮，与其姓名行对齐，不对齐两行总高度 |
| 文本颜色 | 继承当前页面同层级字体颜色，不单独改成绿色号码 |
| 关闭或返回 | 只关闭弹窗并回到帮助与反馈，不自动拨号 |

姓名、电话之间及人员行之间保持紧凑，不用过大留白。标题、正文、辅助文字和按钮尺寸沿用当前基线；不能因内容较长截掉工作日或挤压拨号按钮。

### 5.2 顺序

代理商客服优先于平台客服展示，但不显示类别标题。同类按姓名中文排序；姓名相同时依次按号码、工作时间和稳定来源顺序区分。重复打开或切换演示场景时，不得随机重排或让按钮指向另一位联系人。

### 5.3 电话与工时

每位客服显示自己的姓名、电话及工作时间，不拼接其他人员数据。支持逐日工作时间文案，包括单日、连续工作日、跳日、连续加跳日以及全周组合。例如“每周一、周三、周四、周五、周六、周日 8:30-17:30”须完整展示。

工作时间仅为信息，不因当前时间在范围外就禁止拨打或先插入额外拦截。

号码缺失或无效时不生成错误拨号动作；不能补入默认号码或其他客服号码。号码显示格式可以使用现有格式化方式，但拨打对象始终对应原记录。

## 6. 拨号与关闭

点击某位客服“拨打”才执行该人员对应号码的拨号动作。打开名单、切换场景、滚动、关闭均不拨号。系统拨号取消后，当前帮助页和学校上下文保持。

本地HTML原型仅提示演示拨号并发出演示事件，不实际拨打配置中的电话号码。生产环境的拨号能力由真实小程序适配，失败时不自动改拨另一人。

弹窗复用现有底部弹层及固定首尾结构，内容较长时只滚动名单正文。业务弹层和说明面板关闭顺序按当前框架处理，不能一次返回误退到其他身份或首页。

## 7. 异常、数据刷新与演示说明

| 情形 | 处理 |
|---|---|
| 代理商学校，代理商创建数为0 | 入口及点击均无客服，不回退运营默认客服 |
| 代理商客服数量由0变为有数据 | 重新获取学校上下文和有效配置后展示，不保留无客服缓存 |
| 负责机构或学校发生切换 | 重新解析客服；旧名单不继续用于拨号 |
| 名单为空 | 明确无客服信息，不显示空号码按钮 |
| 平台默认配置缺失 | 不虚构号码，不转拨其他机构 |
| 数据读取失败 | 保留必要出路并提示读取问题，不能用其他学校缓存掩盖错误 |
| 拨号取消或失败 | 保留页面，不自动重拨或替换联系人 |
| 名单较长或工时换行 | 正文可滚动，姓名、号码、工时及按钮归属保持正确 |

演示说明中提供无客服、单客服、多客服、代理商未创建客服不兜底及恢复上下文等场景。未创建客服场景优先级高于演示号码；切到单客服或多客服也不能绕过该条件，必须恢复有效学校上下文后才显示。

本次原型通过本地客服上下文模拟负责类型及创建数量。正式服务须提供可信配置；离线场景不代表后台解析、学校关系更新或真实电话能力已上线。

## 8. 验收清单

1. 联系客服保持帮助与反馈内的直接入口，不新增管理菜单层级。
2. 单人和多人均打开“联系客服”，入口不直接拨号。
3. 代理商负责且创建客服数为0时，无运营默认号码或其他学校号码，点击仅显示无客服信息。
4. 代理商已有客服、平台直营及无学校上下文按各自规则处理，不混用学校或角色。
5. 名单不显示类别标题，顺序稳定；姓名号码同行、工作时间另行、按钮对齐姓名行。
6. 完整工作时间文案可读，不因换行拨错联系人。
7. 点击指定人员只处理其号码；关闭和取消不拨号。
8. 当前FAQ题目、答案及默认收起状态保留，反馈建议不显示多余副文案。
9. 本地原型不触达真实电话；说明与实际场景一致。
10. 未涉及的小程序页面和身份切换保持原样。
