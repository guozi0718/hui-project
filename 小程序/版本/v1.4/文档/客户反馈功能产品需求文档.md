# 智小徽小程序客户反馈功能产品需求文档

文档版本：v1.0  
定版日期：2026-11-25  
适用产品：内置家长、教师两种可切换身份的智小徽小程序  
功能版本：家长端 v0.34、教师端 v0.35；完整小程序定版版本为双端 v1.0。

## 1. 范围与业务闭环

本功能从“我的 → 帮助与反馈 → 反馈建议”进入，包含本人反馈列表、提交反馈表单、反馈详情、附件预览和未提交表单离开确认。

**一条反馈只包含用户一次提交和受理方至多一次公开回复。状态仅“待回复”“已回复”。回复后本条问答结束。**

用户已提交的内容、消息和附件不能修改或删除，同一记录不提供追问、撤回或补充消息。后续问题通过新建独立反馈提出，获得独立编号。小程序不新增后台式“反馈回复”“用户数据查询”菜单，也不开放受理方账号或他人资料查询。

## 2. 身份、记录范围与受理边界

### 2.1 本人记录

记录按当前角色与提交账号隔离。同一账号切换教师、家长身份后，分别展示各自角色提交的记录，不混合。

家长只能查看本人提交的反馈，同家庭其他家长即使关联同一孩子也不可查看。家长本人列表不按当前选择的孩子、学校或当前孩子名单再次过滤；孩子转校、毕业、离校、解绑或退出当前列表，不因此删除本人已提交记录。

教师只能查看本人教师身份提交的反馈，同校其他教师不可查看。教师本人列表不因任职学校切换而筛掉本人提交的记录。教师反馈不关联学生。

### 2.2 受理关系

提交时，根据对应学校当前负责机构配置分配到代理商或运营平台；该受理组织内具备相应权限的账号处理。非受理组织不能查看正文和附件。

待回复时发生学校负责机构转派，按当前配置移交完整业务内容、公开消息和附件；原受理组织失去访问权，提交人本人查看权保留。

小程序来源记录不因教师或孩子属于某学校就对该校后台人员开放。小程序详情只显示公开业务内容，不显示内部处理消息、受理组织内部资料或其他账号记录。

## 3. 我的反馈列表

列表提供“全部”“待回复”“已回复”三个筛选。它们是同一页内的筛选状态，切换不新增业务页面、不修改反馈本身状态。

卡片展示反馈类型、当前状态、正文摘要及最近更新时间；状态和时间按现有布局靠右。整张卡片可进入对应编号的详情，不另放“查看详情”提示。

列表按最近更新时间倒序。新提交进入待回复；受理方回复后为已回复，最近更新时间更新。不同反馈编号独立，不因内容相似合并。

没有本人记录时显示“暂无反馈记录”并保留提交入口；已有记录但筛选无结果时显示对应空态，不能混入其他账号记录。读取失败应显示失败或重试，不以空列表掩盖。

点击底部“＋提交反馈”打开新表单，不复用另一记录的正文、附件或编号。返回列表按当前框架保留应保留的筛选及阅读位置。

## 4. 提交表单与字段

### 4.1 顺序及只读基本信息

表单顺序为基本信息、反馈类型、反馈内容、附件图片，底部固定取消和提交按钮。

| 项目 | 家长端 | 教师端 |
|---|---|---|
| 学校名称 | 表单打开时当前孩子的学校名称 | 当前教师有效任职学校名称 |
| 人员名称 | 学生名称，取当前选中孩子 | 老师名称，取当前登录教师资料 |
| 读取方式 | 当前身份与孩子关系回写 | 当前教师与学校任职关系回写 |
| 可编辑性 | 学校、学生均只读 | 学校、老师均只读 |
| 新建资格 | 当前家长与孩子关系有效，孩子提交时为在读 | 当前教师身份、学校任职关系及现行反馈提交资格有效 |

基本信息放在反馈类型之前；每一行左右边界与同端帮助与反馈的常见问题行对齐。字段名和值使用同一层级常规字重，值不加粗；保持已确定字号、顺序和颜色，不因只读采用错误的禁用提示。

### 4.2 可填字段与校验

| 字段 | 必填 | 规则 |
|---|---|---|
| 反馈类型 | 是 | 问题反馈、功能建议；默认问题反馈，提交前可切换 |
| 反馈内容 | 是 | 去掉首尾空白后不得为空，最多500字，展示字数计数 |
| 附件图片 | 否 | 最多9张，每张不超过10MB；支持JPG、JPEG、PNG |
| 反馈编号 | 系统生成 | 提交成功时生成，编号同时是唯一记录ID，不另外展示第二个记录ID |

表单没有需要用户填写的反馈标题、受理组织或学校人员查询字段。添加图片后可预览或移除，移除只作用于未提交图片。格式、张数或大小不合格时拒绝该项并保留其他有效内容。

图片异步读取中禁止提交；读取失败须明确提示，不能创建正文成功但附件丢失的半条记录。退出后迟到的读取回调不得把图片写回其他表单。

### 4.3 提交时复核

家长提交时复核当前家长角色、账号、当前孩子关系、学校和孩子在读状态。孩子毕业、离校、状态不明或关系失效时不创建新记录，保留有效输入并说明原因。

教师提交时复核当前账号、教师角色、有效学校任职及现行反馈提交资格。学校名称、老师名称无法取得时不能以空值提交；不虚构新的权限码或用原型演示身份代替服务端鉴权。

内容校验通过后创建一个编号和一条首问消息，状态为待回复，进入本人反馈列表。处理期间阻止重复点击产生多条记录。校验或明确提交失败时保留输入；结果不明确时先查询同一提交结果，避免重复新建。

## 5. 返回、取消与放弃编辑

未编辑表单时，顶部返回和底部取消直接关闭，不产生记录。类型、文字或图片已经改变且尚未提交时，先显示手机框内底部确认层：

- 标题：放弃编辑。
- 正文：确认放弃当前编辑内容吗？确认后将清空内容，不可恢复。
- 操作：取消、确认放弃。

点击取消只关闭确认层，表单类型、正文和已选图片保持；点击确认放弃才清空本次未提交内容并退出。该确认不涉及已提交记录，不叫“撤回反馈”。

提交表单复用同页容器，顶部和底部固定，中间正文滚动；不为表单内部选择项和图片预览反复新增页面。

## 6. 反馈详情

### 6.1 信息区

依次显示反馈编号、类型与状态、完整首条反馈正文及其附件。类型与状态同行，状态靠右。首条正文完整展示，不以列表摘要替代。

详情不显示学校、学生快照、联系电话或受理方内部资料；不单列提交时间字段。提交时间显示在“提交”沟通消息右侧。基本信息卡只出现在新建表单。

### 6.2 沟通记录

待回复记录展示一次提交及其时间；已回复记录再展示受理方一次公开回复及时间。按消息发生时间倒序，时间靠右，首条提交动作保留。

来自代理商或运营后台受理方的回复统一显示“平台客服 回复”，不附加客服姓名或括号。提交人的显示称谓保持当前角色规则，不能替换成平台客服。

已提交内容、公开回复和附件均只读。详情不存在追问、撤回、修改、删除按钮，不提供这些动作的弹窗或API触发入口。需要新问题时返回列表新建反馈。

### 6.3 附件

附件归属对应消息；点击缩略图打开该图片，关闭回到当前详情，不切换记录或新增一条反馈。图片不可读取时保留正文、状态和关闭入口，不用其他记录图片替代。

## 7. 状态与业务信息

| 信息 | 当前规则 |
|---|---|
| 唯一标识 | 反馈编号即记录ID |
| 初始状态 | 待回复 |
| 回复后状态 | 已回复，本条问答结束 |
| 公开消息数量 | 一条首问、至多一条公开回复 |
| 提交人身份 | 保存提交角色与账号，用于本人隔离 |
| 提交时信息 | 保存必要姓名、学校及家长端学生关系资料，供受理和权限识别；详情不回显快照 |
| 附件 | 按提交消息关联，提交后不修改 |
| 通知与记录状态 | 通知发送失败不等于未创建记录，也不能把待回复改成已回复 |
| 已回复记录 | 用户只读，不能继续在原编号发消息 |

## 8. 异常与恢复

| 场景 | 页面与业务结果 |
|---|---|
| 当前账号或角色变化 | 重新核对范围，不混入另一角色记录 |
| 编号错误或不是本人记录 | 拒绝展示并返回本人列表，不泄露正文、附件或编号归属 |
| 家长孩子关系或在读资格变化 | 拒绝新提交并保留表单，不删除本人已提交记录 |
| 教师任职或提交资格失效 | 拒绝新提交，历史本人查看按现行本人范围处理 |
| 受理方回复，列表仍为待回复 | 读取最新状态和唯一回复，不能继续发送第二问 |
| 正文为空或超限 | 指出原因，不创建编号，保留输入 |
| 图片不合格或读取失败 | 拒绝该项，保留其他有效内容 |
| 提交失败或结果不明 | 不丢表单，不产生重复编号；必要时先核对结果 |
| 列表或详情读取失败 | 显示失败和必要重试，不伪装成无数据 |
| 图片访问失败 | 保留业务信息与时间，单独处理图片错误 |

## 9. 样式、演示与实现边界

反馈页面保持同端框架，标题约16.5px，正文和选项13px，字段标签12px，辅助文字约11.5px；基本信息字段名和值为常规字重。不得将这些局部字号规则扩大应用到未涉及的业务页面。

演示说明分别解释教师提交资格和家长孩子关系、在读状态；可预览空态、正文和附件校验、资格失败及放弃编辑。场景应在对应页面说明内切换，不向业务流添加后台管理入口。

HTML原型使用本地演示账号、记录和图片读取，反馈内容仅按其演示生命周期保存，不表示生产数据库、真实受理方、通知投递、上传存储和权限服务已上线。生产端需对账号、角色、对象和受理关系重新鉴权，并保证提交幂等及附件访问授权。

## 10. 验收清单

1. 本人账号与教师/家长角色记录正确隔离，无用户数据查询入口。
2. 列表只有全部、待回复、已回复，整卡可打开正确编号详情。
3. 提交表单基本信息位置、学校/老师或学生资料、行宽和常规字重正确。
4. 家长非在读或关系失效不能新建；教师任职或提交资格无效不能新建。
5. 正文500字、图片9张、每张10MB及格式限制正确，失败不丢有效内容。
6. 一次创建只产生一个编号；状态为待回复，受理方最多一次回复。
7. 详情只读且消息倒序，平台答复显示“平台客服 回复”。
8. 不存在追问、撤回、修改、删除入口及其弹窗；后续问题独立新建。
9. 未编辑直接取消，编辑后取消先确认；取消确认层保留输入，确认放弃才清空。
10. 图片预览、返回、角色切换、演示说明与其他业务保持既定框架。
