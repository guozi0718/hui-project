### 学校反馈一期产品需求文档｜学校端

产品版本：V1.0.0（第一期，新增功能）  
文档编号：PRD-FB-SCH-20261125  
文档版本：V1.0  
适用端：学校端（学校后台）

---

#### 1. 需求背景与业务目标

学校后台需要为本校管理人员提供统一的问题反馈与功能建议入口，便于学校向对应受理方（代理模式下为本校所属代理商，直营模式下为运营平台）提交日常使用问题或产品建议，同时集中查看本校范围内的反馈记录与受理答复进度。

本期核心目标：

1. **本校反馈提交与单轮问答闭环**：学校管理人员可在学校后台提交新的“学校端”反馈（含反馈类型、标题、正文及可选图片附件），按本校当前受理模式自动分派至所属代理商后台或运营后台处理。每条反馈采用“提交人提问 1 次 ＋ 受理方公开回复至多 1 次”的单轮问答闭环，收到受理方答复后本条反馈即完结，状态由“待回复”变为“已回复”。
2. **三类本校来源反馈集中查阅**：学校端列表集中展示归属于本校的三类来源反馈——本校管理人员提交的“学校端”反馈、本校教师通过小程序提交的“教师端”反馈、本校在读学生家长通过小程序提交的“家长端”反馈；其中教师端与家长端反馈在学校端仅提供只读查看，不开放学校端回复、编辑或删除。
3. **学校专属字段与隐私边界清晰**：学校端所有记录均归属于当前登录学校，筛选区、列表及详情弹窗均不展示“所在区域”“所属单位”“所在机构”等跨校组织字段；家长来源反馈在列表与详情中紧跟“联系电话”展示提交时保存的“关联学生”姓名快照；受理方（无论代理商还是运营平台）发出的公开回复在学校端统一显示为“平台客服”，不暴露客服个人姓名与内部沟通记录。
4. **精准操作留痕**：学校人员成功提交一条“学校端”反馈后，自动在“系统设置 → 操作日志”中新增 1 条操作类型为“提出反馈”的记录；纯查看、筛选查询、校验拦截、无权访问以及家校通知模块的所有操作均不写入该操作日志。

#### 2. 一期功能范围

##### 2.1 本期包含范围

| 功能模块 | 学校端业务范围 |
| --- | --- |
| 学校反馈列表 | 位于一级主菜单“学校反馈”；展示当前学校范围内的“学校端、教师端、家长端”全部有效反馈记录；支持按反馈来源、反馈人、联系电话、反馈类型、状态组合筛选，按最近更新时间倒序排列，支持每页条数切换与页码跳转。 |

| 反馈详情查看 | 弹窗只读展示反馈人信息（来源、反馈人、完整联系电话、关联学生）、反馈类型、反馈编号、当前状态，以及按时间由近到远倒序排列的沟通记录与附件缩略图；受理方回复统一展示为“平台客服”。 |
| 附件原图预览 | 在新增反馈表单与反馈详情弹窗中，点击任意图片缩略图可展开原图预览层查看完整图片，支持一键关闭回到原弹窗。 |
| 放弃未保存内容确认 | 新增反馈弹窗内存在未提交的填写内容或已选附件，触发右上角关闭、键盘 `Esc` 或切换菜单/页签时弹出离开确认，防止误操作丢失输入。 |
| 学校操作日志 | 位于“系统设置 → 操作日志”，专门记录并查询学校人员成功提出反馈的记录；支持按反馈编号或反馈主题关键词检索，按操作时间倒序展示。 |
| 原型状态演示面板 | 学校反馈页面及各弹窗右上角提供“演示说明”入口，用于评审与验收阶段按当前页面上下文快捷预览空态、校验拦截、并发冲突、加载失败与无权限等状态。 |

##### 2.2 本期不包含范围

本期不包含：学校端回复教师或家长反馈、对已提交反馈进行修改/删除/撤回/追问、查看或导出客服内部处理备注、展示短信或小程序通知的送达状态与失败重试、在学校端跳转运营后台查看跨端人员线索、跨校汇总查看其他学校反馈。

#### 3. 核心业务概念、权限矩阵与全局一致性规则

##### 3.1 核心业务对象与基础规则

| 业务概念 | 业务定义与数据来源 | 一期核心业务规则 |
| --- | --- | --- |
| 反馈记录 | 一次独立的问题反馈或功能建议档案 | 提交成功时由系统生成唯一反馈编号（如 `SK202611200001`），作为整条反馈及后续受理回复、操作日志的唯一关联凭证；不同记录即使内容相似也各自独立、绝不合并。 |
| 反馈来源 | 发起该条反馈的业务端口 | 学校端可见枚举固定为三类：`学校端`、`教师端`、`家长端`；来源在提交成功瞬间由发起端身份锁定，后续不可修改。 |
| 受理模式与流转路线 | 决定本校反馈由谁受理回复 | 按当前学校所处服务模式自动分配：学校处于**代理模式**时流转至所属代理商后台处理；处于**直营模式**时流转至运营后台处理。若待回复期间学校负责机构发生转归，整条未回复记录随新负责机构移交，学校端查看权限不受影响。 |
| 关联学生快照 | 家长提交反馈时所选孩子的学生姓名 | **家长端**来源记录在提交成功瞬间捕获并固化当前选中学生的姓名快照，后续学生改名、转班、毕业、离校或家长解绑均不改写该历史快照；**学校端**与**教师端**来源反馈不关联学生，统一显示`—`。 |
| 单轮问答与状态机 | 反馈全生命周期状态 | 状态仅两种：**`待回复`**（刚提交，等待受理方答复）与**`已回复`**（受理方已发出唯一一次公开回复，问答结束）。提交后不可修改、不可删除、不可撤回，也不支持在原编号下继续追问；如有新问题须另行新建反馈。 |
| 平台客服展示称谓 | 受理方回复在学校端的统一展示名称 | 无论是所属代理商客服还是运营后台客服发出的公开回复，在学校端反馈详情中统一显示为**“平台客服”**，不展示客服个人姓名、工号或受理机构内部名称。 |
| 联系电话展示规则 | 反馈人账号绑定或提交时记录的手机号 | 列表页为保护隐私进行中间四位脱敏展示（如 `138****8211`），无号码显示`—`；详情弹窗面向本校授权人员完整展示号码，缺失显示`—`。 |
| 反馈附件 | 随首条反馈或受理回复附带的图片凭证 | 仅支持 `JPEG`、`JPG`、`PNG` 格式图片，单条消息最多 9 张、每张不超过 10MB；附件与所属消息强绑定，提交后不可增删或替换。 |
| 操作日志记录口径 | 学校端“系统设置 → 操作日志”的入库范围 | 仅在学校人员于学校端**成功提交“学校端”反馈**时写入 1 条日志，操作内容固定为`提出反馈`；查看详情、筛选查询、校验不通过、权限拦截及家校通知操作一律不记入日志。 |

##### 3.2 角色权限与数据范围矩阵

| 权限控制项 | 学校端可见与可操作范围 | 权限校验时机与无权限表现 |
| --- | --- | --- |
| 学校反馈页面访问 | 具备“学校反馈”查看权限的当前学校账号 | 左侧导航菜单展示、通过书签/链接直达、每次刷新与查询翻页时均校验。无权限时隐藏菜单；直接进入页面时工作区居中提示**“当前账号没有学校反馈权限，请联系管理员。”**，不展示任何反馈记录或新增按钮，其他有权菜单保持可用。 |
| 新增学校反馈 | 具备“学校反馈－新增”权限的当前学校账号 | 渲染“新增反馈”按钮、打开新增弹窗、最终点击“确定”提交时均校验。无新增权限时隐藏或禁用按钮；强制触发提交时拦截并提示无权限。 |

| 操作日志查看 | 具备“系统设置 → 操作日志”查看权限的当前学校账号 | 进入操作日志页、关键词查询、重置及刷新时均校验。日志查看权限与反馈新增权限相互独立；无权查看时清空日志表格并提示无权限。 |

##### 3.3 全局数据一致性、并发状态与动态权限变化总则

1. **提交防重与结果确认原则**：新增反馈点击“确定”提交后，按钮立即变为“提交中…”并置灰禁用，同时屏蔽回车重复提交，防止连续点击生成两条重复编号。若因网络波动超时未收到明确结果，提示**“请求超时，操作结果未确认。请先核对反馈列表后再重试，避免重复提交。”**，保留当前表单内容供核对；同一笔提交请求系统防重，绝不重复建单或重复写入操作日志。
2. **跨端状态实时同步原则**：当学校人员停留在反馈列表或详情页期间，受理方（代理商或运营后台）恰好完成了回复，学校端刷新列表或重新打开详情时立即同步显示为**“已回复”**状态及最新“平台客服”回复内容，并按新更新时间重排列表顺序；受理方回复过程中或回复完成后，学校端均不出现可修改或追问的入口。
3. **附件异步读取完整性原则**：选择本地图片后正在读取校验期间，禁止提交表单（提示**“附件读取中，请稍候”**）；单张图片读取失败或格式不合规时明确提示原因，绝不悄悄丢弃该附件后把残缺表单提交出去。若用户关闭弹窗后之前未完成的图片读取才返回，直接丢弃，严禁写入下一次新打开的表单。
4. **停留期间权限动态回收与账号切换原则**：
   - **仅收回新增权限（仍保留查看权）**：在已打开的新增弹窗中点击“确定”时拦截并提示**“权限已变更，当前操作无权限。”**，不写入数据与日志；列表与详情查看仍可正常使用。
   - **收回页面查看权限**：立即清空列表数据、统计条数、详情弹窗及操作日志内容，提示权限已变更；此前发出的慢响应查询延迟返回时直接丢弃，严禁重新覆盖界面。
   - **登录失效或切换学校/账号**：登录过期提示**“当前操作人身份失效，请重新登录后操作”**；同一浏览器切换其他账号或切换学校身份时，立即彻底清空上一账号的筛选词、列表结果与未提交表单，按新账号与新学校权限重新加载；权限恢复后不自动重放此前被拦截的提交。
5. **反馈创建与日志写入原子一致原则**：只有反馈正式创建成功时才同步生成“提出反馈”操作日志；校验失败、取消关闭、无权限拦截或保存失败均不得残留孤立日志。
6. **全局无数据展示统一原则**：本模块所有列表及表格（含学校反馈列表、学校操作日志列表）在初始无数据或筛选无匹配结果时，**均保持页面原本框架完整不变（顶部标题、筛选区、操作工具栏及表格表头标题行全部保留）**，表格数据区**仅在第一行合并所有列居中展示“暂无对应数据”**（仅此一行），且**不显示底部分页栏（无分页）**。

#### 5. 功能详细说明

---

##### 5.1 学校反馈列表页（FB-01）

###### 5.1.1 页面定位与整体规则

1. **菜单入口与页签行为**：位于学校后台左侧主导航一级菜单`学校反馈`。学校后台所有一级菜单默认折叠；点击进入后在顶部页签栏打开“学校反馈”页签；关闭当前页签优先回到左侧相邻页签，全部关闭时回到首个一级菜单下的首个二级菜单。
2. **页面布局结构**：内容区左右保留统一留白（24px），从上至下依次为：多条件筛选查询区 → 列表工具栏（左侧“新增反馈”主按钮）→ 9 列反馈数据表格 → 底部分页与页码跳转栏。
3. **默认排序与首次状态**：首次进入全部筛选项默认为“全部”或空，默认展示第 1 页、每页 10 条。列表按**记录最后更新时间从新到旧倒序排列**（新提交反馈、受理方回复均会刷新最后更新时间）；更新时间相同时按提交创建时间倒序，仍相同时按反馈编号稳定倒序，翻页不乱序。
4. **弹窗落点与上下文保持**：从列表打开“新增反馈”或“反馈详情”后，无论是取消、关闭还是提交成功，均停留在当前“学校反馈”列表页；查看详情关闭后保留当前筛选条件与页码，新增反馈提交成功后刷新列表使新记录置顶展示。
5. **加载与空态严格区分**：
   - 首次读取或查询未返回时展示“加载中…”，不提前闪现无数据提示；
   - 读取失败或网络超时展示**“反馈列表查询失败，请重新查询。”**并提供重试入口，保留用户已输入的筛选条件，**严禁把查询失败显示成“暂无对应数据”**；
   - 本校尚无任何反馈记录或输入筛选条件后无匹配结果时，**保持页面原本框架不变（筛选区、“新增反馈”工具栏及 9 列表头标题行全部保留），表格数据区仅第一行合并所有列居中显示“暂无对应数据”（仅此一行），且不显示底部分页栏（无分页）**；筛选无匹配时支持点击“重置”快速恢复全量列表。

###### 5.1.2 筛选查询区

筛选条件从左到右固定 5 项，**严禁出现“所在区域”“所属单位”“所在机构”筛选项**：

| 筛选项顺序与名称 | 控件类型与必填 | 默认值与占位提示 | 选项枚举与匹配规则 |
| --- | --- | --- | --- |
| 1. 反馈来源 | 下拉单选框；非必填 | 默认“全部” | 枚举：`全部`、`学校端`、`教师端`、`家长端`；按精准来源匹配（置首排列） |
| 2. 反馈人 | 单行文本输入框；非必填 | 默认空；占位“请输入反馈人姓名” | 最多 50 字；去除首尾空格后，按包含关键词模糊匹配反馈人姓名 |
| 3. 联系电话 | 单行文本输入框；非必填 | 默认空；占位“请输入联系电话” | 去除首尾空格后，按连续数字片段模糊匹配反馈人完整联系电话（支持按原号段匹配，不受列表脱敏影响） |
| 4. 反馈类型 | 下拉单选框；非必填 | 默认“全部” | 枚举：`全部`、`功能建议`、`问题反馈` |
| 5. 状态 | 下拉单选框；非必填 | 默认“全部” | 枚举：`全部`、`待回复`、`已回复` |

**筛选交互、逻辑校验与异常场景**

1. **查询生效时机**：修改下拉选项或输入文字过程中不实时刷新表格；点击右侧绿色**“查询”**按钮或在输入框内按回车键后，所有非空条件按**“同时满足（且）”**关系执行过滤，并自动回到第 1 页。
2. **重置规则**：点击**“重置”**按钮，将全部下拉项恢复为“全部”、清空文本输入框、回到第 1 页并立即重新加载本校全量反馈列表（每页条数保持当前选择）。
3. **请求中与权限隔离**：查询处理期间“查询”按钮防重复点击；任何筛选组合均严格限定在当前学校授权数据范围内，严禁通过输入他人手机号或姓名查出外校记录。

###### 5.1.3 列表字段与分页

**表头顺序（共 9 列，固定左→右）**：`反馈来源` → `反馈人` → `联系电话` → `关联学生` → `反馈类型` → `反馈内容` → `反馈时间` → `状态` → `操作`（不展示所在区域、所属单位或所在机构）。

| 列顺序与字段名 | 数据来源与展示规则 |

| 2. 反馈人 | 展示提交该反馈时的反馈人姓名快照；缺失显示`—` |
| 3. 联系电话 | 展示反馈人脱敏手机号（如 `138****8211`）；缺失显示`—` |
| 4. 关联学生 | 紧跟“联系电话”列：**家长端**来源展示提交时保存的学生姓名快照（如`林晓乐`）；**学校端**与**教师端**来源固定显示`—` |
| 5. 反馈类型 | 展示`问题反馈`或`功能建议`，列标题与内容居中对齐 |
| 6. 反馈内容 | 展示首条反馈正文摘要，超出列宽以单行省略号截断，鼠标悬停显示完整正文提示 |

**分页交互、校验与异常场景**

1. **分页控件与无数据隐藏规则**：有数据时底部展示总条数（`共 X 条数据`）、每页条数下拉（支持 `10 / 20 / 50 / 100` 等，默认 `10`）、上一页（`‹`）、页码按钮、下一页（`›`）、页码跳转输入框（`跳至 [ ] 确定 / N 页`）。**当列表无数据或筛选无匹配结果时，不展示底部分页栏（无分页）。**
2. **边界与非法页码拦截**：处于第 1 页时上一页禁用，处于末页时下一页禁用；切换每页条数后自动回到第 1 页。在“跳至”输入框输入非整数、小于 1 或大于总页数的数字并点击“确定”时，拦截并提示**“请输入 1-N 之间的页码”**，保持原页码不变。
3. **列表刷新页码修正**：若数据变化导致总页数减少、原页码超出有效范围时，自动回退至最新有效末页，不展示空白页。

###### 5.2.1 字段定义

| 字段名称 | 必填 | 默认值与占位提示 | 控件形态、格式与业务约束 |
| --- | --- | --- | --- |
| 反馈类型 | 是 | 默认未选，占位文字“请选择” | 下拉单选框（带必填星号），下拉可选项仅包含`功能建议`、`问题反馈`（**“请选择”仅作未选时的灰色占位提示文字，展开下拉列表后不作为可选条目出现**） |

| 反馈内容 | 是 | 默认空 | 多行文本输入框（带必填星号），最多输入 200 字；去除首尾空格后长度须为 1—200 字 |
| 附件 | 否 | 默认无附件 | 点击“选择文件”按钮唤起本地图片选择器（支持多选）；下方辅助说明固定为：`支持JPEG、JPG、PNG格式图片，最多九张，每张大小不超过10M。` 已选图片以缩略图网格展示，支持点击放大预览（5.4）及点击右上角`×`移除单张图片 |

###### 5.2.2 字段校验、提交流程与异常场景

1. **反馈类型校验**：未选择反馈类型点击“确定”，提示**“请选择反馈类型”**，保留其余已填内容，不关闭弹窗。
2. **反馈标题校验**：未填、仅输入空格或超过 50 字点击“确定”，提示**“请输入1-50字反馈标题”**，保留表单内容。
3. **反馈内容校验**：未填或仅输入空格点击“确定”，提示**“请填写内容”**；超过 200 字提示**“内容不能超过200字”**，保留表单内容。
4. **附件上传与校验**：
   - 累计选择超过 9 张（含分批多次选择累计超 9 张）时，拦截本次追加并提示**“最多选择9张图片”**，保留此前已成功添加的有效图片；
   - 选择非 `JPEG / JPG / PNG` 格式文件、伪装后缀的非法文件或单张超过 10MB 的图片时，拦截并提示**“支持JPEG、JPG、PNG格式图片，单张不超过10M”**，不影响已添加的合法图片；
   - 图片读取失败时提示**“图片读取失败”**，不添加破损占位图；
   - 附件尚在异步读取期间点击“确定”，拦截并提示**“附件读取中，请稍候”**；
   - 移除已选图片仅作用于当前未提交表单，不产生日志。
5. **正常提交结果**：全部字段与权限校验通过后，系统按当前学校所处受理模式（代理模式→所属代理商；直营模式→运营平台）创建一条`学校端`新反馈，自动生成唯一反馈编号，状态置为`待回复`，同步向“系统设置 → 操作日志”写入 1 条`提出反馈`记录；关闭弹窗、弹出轻提示**“已提交”**并刷新列表（新记录置顶）。**提交成功后不可在学校端修改标题、类型、正文或附件，也不可删除或撤回。**
6. **提交中、网络失败与权限异常**：
   - 提交中“确定”按钮置灰显示“提交中…”防连点；
   - 保存明确失败提示**“提交失败，请重试。”**，保留全部已填文字与已选附件，不生成日志；
   - 网络超时未收到明确结果提示**“请求超时，操作结果未确认。请先核对反馈列表后再重试，避免重复提交。”**；
   - 提交瞬间账号新增权限被收回提示**“权限已变更，当前操作无权限。”**，登录过期提示**“当前操作人身份失效，请重新登录后操作”**。
7. **取消与未保存离开关闭规则**：
   - 点击底部**“取消”**按钮：无论是否已填写内容或上传图片，直接关闭弹窗并清空未提交内容，不弹二次确认框；
   - 点击右上角**“×”**、按键盘 **`Esc`** 或切换菜单/页签：若存在未提交的填写或附件改动，弹出 5.5《放弃未提交内容？》确认弹窗；若未做任何修改，直接关闭弹窗。

3. **关闭返回**：点击底部`关闭`、右上角`×`或按`Esc`，关闭详情弹窗并停留在原列表页，完整保留原筛选词、页码与滚动位置。

| 当前适用场景 | 仅列出当前所处列表或弹窗适用的状态切换项（如列表页：无数据、无匹配、加载中、查询异常、加载超时、无权限、提交校验、记录已变化；弹窗页：加载失败、权限失效、对象失效、必填校验、附件校验、版本冲突、提交失败、结果未知）。其中预览“无数据 / 无匹配”时，须严格保持原本框架与表头标题行，仅在表格第一行合并显示“暂无对应数据”并隐藏分页，不得隐藏整张表格 |
| 互斥切换与恢复默认 | 同一时刻仅生效一种异常模拟状态，切换新状态自动替换旧状态；提供“恢复默认”按钮，点击或离开当前弹窗/页面后立即恢复正常业务展示 |
| 数据安全隔离 | 在演示说明中触发任何异常预览均不改写或删除既有业务记录，也不写入学校操作日志 |

#### 6. 跨端协同与界面交互通用规范

##### 6.1 多端数据联动关系

| 联动场景 | 跨端业务规则 |
| --- | --- |
| 学校端提交 → 受理端处理 | 学校端提交的“学校端”反馈按当前学校受理模式实时进入所属代理商后台（代理模式）或运营后台（直营模式）的待回复列表；受理方发出唯一一次公开回复后，学校端列表状态同步更新为“已回复”，详情时间线顶部展示“平台客服”回复内容与附件。 |
| 小程序提交 → 学校端只读查阅 | 本校教师在教师小程序、本校在读学生家长在家长小程序提交的反馈，同步归入本校学校端列表（分别标示`教师端`、`家长端`；家长来源带提交时学生姓名快照），学校端仅可查看详情，不可代替受理方回复。 |
| 受理模式变更与学校转归 | 若待回复反馈所属学校在运营后台发生负责机构转归（如由 A 代理商转为 B 代理商或转平台直营），待回复记录连同原正文与附件移交新受理方继续处理，原受理方失去访问权，学校端仍保持正常查看与等待回复。 |

##### 6.2 统一版式与交互规范

1. **页面留白与对齐**：学校反馈内容区左右保持 24px 统一留白；筛选条件标签与控件水平对齐，表格与操作栏在内容容器内齐平；菜单与顶部页签不展示小红点。
2. **弹窗固定首尾**：新增反馈弹窗、反馈详情弹窗、放弃确认弹窗及原图预览层在内容超长或小屏下，顶部标题栏与底部操作按钮栏始终固定可见，仅中间内容区独立纵向滚动。
3. **按钮语义统一**：普通表单确认类操作统一使用“取消 / 确定”配对布局（取消在左、确定在右）；纯只读详情弹窗底部仅提供“关闭”按钮。

#### 7. 核心验收清单

| 验收模块 | 核心验收检查要点 |
| --- | --- |
| 菜单与列表 | 一级菜单默认折叠，“学校反馈”页签切换与关闭回退正常；列表严格展示 9 列（含“关联学生”紧跟“联系电话”），筛选严格展示 5 项（“反馈来源”置首），筛选、列表、详情均无“所在区域 / 所属单位 / 所在机构”；无数据或无匹配时保持原本框架与表头标题行，数据区仅首行显示“暂无对应数据”且无分页。 |
| 三类来源与快照 | 列表与筛选准确覆盖本校“学校端、教师端、家长端”三类来源；家长端关联学生显示提交时学生姓名快照，学校端与教师端显示`—`；教师/家长反馈在学校端仅可只读查看，无跳转运营后台的线索入口。 |
| 新增反馈与校验 | 反馈类型、标题（1—50 字）、正文（1—200 字）必填与去空校验准确；附件仅限 JPEG/JPG/PNG、最多 9 张、单张≤10MB，读取中禁止提交；提交成功后状态为“待回复”并按受理模式分派，不可修改、删除或撤回。 |
| 反馈详情与时间线 | 反馈人信息与反馈内容分区清晰，反馈编号位于内容区；消息按时间倒序排列；代理商/运营回复统一展示为“平台客服”；无回复、追问、编辑、删除按钮；附件缩略图可点击放大预览，`Esc` 优先关闭预览层。 |
| 取消与离开确认 | 新增表单点底部“取消”直接关闭清空不弹窗；有未提交内容时点右上角 `×`、`Esc` 或切换菜单/页签弹出“放弃未提交内容？”确认框。 |
| 学校操作日志 | 仅学校端成功提出反馈写入“系统设置 → 操作日志”，操作内容固定为“提出反馈”；查看、查询、校验失败、无权及家校通知操作均不写日志；关键词搜索编号/主题及重置、倒序展示正常。 |
| 异常场景与动态权限 | 查询失败不误报为空列表；提交中防连点、超时防重复建单；无权进入拦截、停留期间收回写权禁止提交、收回读权或切换账号立即清空无权数据；右上角演示说明面板按当前页面上下文隔离切换。 |
